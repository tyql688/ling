# Interface design and component ownership

Ling's application uses one control system. Visual fixes belong to the owning component. [Architecture](architecture.md) describes runtime and state ownership.

## Layout and behavior

First launch opens the Composer with No project selected. This target uses a persistent Ling-managed directory; its conversations share working files. A missing model connection opens the existing provider setup flow while keeping the draft. The target picker and sidebar use a conversation icon and localized name, and the details explain the shared folder. Opening a project selects that project for a new conversation; existing sessions keep their cwd, drafts and reading worksets. Explicit project-scoped actions take precedence over the remembered last conversation target; the managed target is the default when neither exists. The managed target supports conversations, files, terminal and resource settings, and its actions preserve the Host-owned directory lifetime. Closing the last user-selected project leaves the managed conversation target available.

The workbench has left navigation, a conversation and a right reading column. The right column holds one row of tabs: files, diffs and every session tool (Changes, Terminal, Skills, Project Pi configuration, Extension dock, Todo, Questions and Background tasks) open there, and the new tab page offers project file search, the tools and uncommitted changes with file search as its file entry point. Each + action appends a distinct new tab page. Choosing a tool replaces the active new tab page in place. The Files action turns it into Open file with an empty content prompt and the project tree; selecting a file replaces that Open file tab. Further files open in additional retained tabs. If the chosen file or tool is already open, consume the launcher and activate the existing tab with its state intact. The file tree appears only beside this browser or an open file. An open right column always has a tab; closing its last tab closes the column, and collapsing it retains its tabs for restoration. Files, Changes and Skills use the same reading layout: content on the left and a resizable navigation tree on the right. Files remain open until closed. Selecting a change or skill updates the existing tool page within its existing tab. The file tree and skill catalog remain visible; skill resources appear beneath the catalog. Changes group paths by directory. Skill selections, resource selection and reading position belong to the session. At narrow widths, a navigation/content toggle keeps both surfaces accessible without replacing the editor. Navigator width is shared across these readers. Closing a reading tab preserves its source session and unsent Composer. Terminals belong to the project: closing the Terminal tab hides them while their processes keep running. Expanding the right column reuses the same editor and draft owner. The main area shows one selected conversation with its title and action menu. Select conversations from the left sidebar or navigation history; switching retains each session's draft, transcript position and reading workset. Only the right column uses tabs: single-click opens a retained file tab, and each tool has one tab per session. Tab actions belong in the context menu. Closing the focused conversation returns to the home view without deleting it; tab-switch shortcuts apply only to the visible reading area.

The conversation title and the right-column tabs share one 44px top row; only a narrow window places the tabs below the titlebar. In the normal split, the title follows the conversation column's width. When the right column expands, the title becomes a compact, muted conversation icon and name with its action menu. Reading tabs follow immediately, long titles truncate, and one shared reading surface backs the whole row across the available width. Tabs have 36px targets. The expand/restore reading control sits immediately to the left of the close-panel control. By default the right column leaves the conversation about 500px, never exceeds a 16:10 box of the available height, and keeps the conversation at least 352px wide; a dragged split is remembered as a proportion, so window resizes keep it. In the normal split, one conversation backdrop extends through its title to the top of the window, as one continuous surface. Right-column panes retain their own surface and foreground tokens over that backdrop. The tab row, the content and the docked tree each paint exactly one material layer, because nested fills compound translucent skins. File viewers inherit the reading pane's fill and backdrop filter. Keep native window controls and draggable space available. A button centered on the conversation/reading divider swaps the two panes. Their titlebars follow the panes, while the project sidebar stays in place. The reading pane retains its internal content/tree order. Swapping preserves widths, drafts, editor identity and reading positions; the order is saved with the window layout and restored after leaving expanded or narrow mode.

The scheduled-tasks page uses the same 44px window titlebar and sidebar controls as the workspace. Use the sidebar to return to the workspace.

The sidebar's today-usage summary refreshes on session changes while visible and checks external Pi activity every five minutes. Hidden windows defer scans until visible. Relative session timestamps update on their own clock.

The sidebar bell switches between the ten most recently active sessions and the project-grouped list, and the choice persists. The enabled bell uses the skin accent. In the project-grouped list, pinned sessions appear only in their own section, and project headers reveal new-conversation and project actions on hover or keyboard focus. Session rows keep titles aligned: one trailing status or time, with unread sessions marked by a leading accent dot. Hover and keyboard focus replace the trailing slot with row actions; the status remains in the row's accessible name and tooltip.

The current turn's work stays expanded as intermediate assistant replies and tool calls alternate. Earlier work remains open while the reply and subsequent tool calls stream. Manual disclosure choices still apply; settled turns retain their process fold.

Assistant prose keeps its mounted content through tool-call transitions and settlement. When a turn finishes, its work folds away while the terminal reply remains in place and gains its message actions. Completed work retains its folded state during background title generation. The transcript virtualizer measures mounted Markdown to manage visibility and geometry. Code stays readable at its actual height until syntax highlighting has rendered. New text uses a short opacity fade; streaming updates layout immediately and retains settled paragraphs.

Quickstart and conversations share the Composer's surface, controls and draft projection. Selecting a folder or changing language must preserve editable content, selection and undo history. Mode changes save on selection; confirmation belongs to an actual approval request. The permission system adapter supplies policy selection to the shared Composer and approval controls.

Files and media appear in one attachment area above the Composer text. Adding an existing file reference reuses the same attachment. Text editing and undo do not remove attachments. Images show thumbnails; supported audio and video open with playback controls. A failed preview retains its file card and download action. Attachment previews return keyboard focus to their trigger on close. When the home Composer exceeds the available height, the page scrolls so its editor and send controls remain reachable.

Composer completions open above the full input width and remain within the available viewport. Session commands, extension commands, skills and prompt templates have separate headings; project references show file names and paths. Names, descriptions and argument hints remain readable with natural wrapping. Search uses both invocation names and descriptions, including localized text. Quickstart offers the selected project's skills and files before a session exists. Arrow keys select, bare Enter or Tab accepts, and Escape dismisses without changing the draft; subsequent editing reopens suggestions. Focus remains in the editor with an active-descendant link to the listbox. Failed lookups show their error and offer pointer or Enter retry; changing the query or project invalidates the old selectable results.

Web folder selection browses the computer running Ling: users can enter a path, visit the home or parent directory, show hidden folders, and select the current folder. Failed reads stay visible, unavailable links remain marked, and bounded listings disclose omitted entries. A cancelled or superseded browse cannot update a later selection. Desktop uses the system folder picker; browser-local file handles cannot identify a remote Host project path.

Interface zoom must preserve anchored menus, scrolling and keyboard selection in both products. Web uses CSS zoom; Desktop uses native page zoom. The Floating UI Core and DOM ES module entries carry the [upstream CSS zoom correction](https://github.com/floating-ui/floating-ui/pull/3492), which is absent from the published 1.8.0 packages. Remove these patches when the dependency includes that correction, after checking menu placement and selection at 80%, 100% and 150% in Web and Desktop.

Centered dialogs divide their viewport width and height limits by the browser shell's CSS zoom factor. Native page zoom keeps that factor at one because Electron already adjusts the CSS viewport. Dialog form bodies scroll within these limits while their actions remain reachable.

Session analysis and provider quotas use compact inspectors with 44px headers and divided disclosure rows. Keep account limits, balances and model/tool breakdowns in lists; charts and provider glyphs appear within those rows. Session analysis keeps its height stable while sections expand. Details mount on first expansion, preserve their selection until the dialog closes, and use brief opacity/transform motion. Missing or failed quota data remains explicit.

The default interface is monochrome with sparse accent. Settings use divided rows, modest headings and short descriptions. A narrow viewport stacks field labels above controls. Selecting any settings entry closes the navigation sheet, including feature entries and the already active page. Workbench tools use compact panels; full settings-page padding must not consume a narrow sidebar. Product screens show configuration and failures. Show implementation paths when the user is editing those paths; keep build hashes in diagnostics.

The desktop update control appears at the top right of the left sidebar in both the workspace and Settings when an update is available, downloading, ready to install, installing or needs attention after an error. It stays hidden during background checks and when the app is current. Available updates download with one click; downloaded updates restart and install with one click. Progress and error controls open a shared status dialog. Settings → General → About and the native Ling menu provide manual update checks. The native Ling menu also opens Settings, which uses the platform modifier with comma. Installed desktop builds check ten seconds after startup and every four hours while running. Automatic downloads default on and begin when a check finds an update or the preference is enabled with an update available. Downloads continue when the dialog closes. Downloaded updates install on explicit restart or normal quit after owned work drains.

Long settings option groups use the shared stacked field layout. Pi default tools place their label and description above an equal-width grid that adapts to the available content width, so the sidebar and interface zoom cannot squeeze the description into a narrow column.

Pi default tools have an explicit restore action; clearing every choice disables standard tools while extension activation rules still apply. Codemode offers combined or script-only access and an editable inline catalog budget. The composer retains a virtual model selection and shows its latest physical route beside it, with context usage based on that physical model. Running nested calls appear below their parent tool; completed calls use the persisted result tree. Generated images share the conversation's image preview, zoom and download controls.

## Menus and focus

Selects, dropdown menus and context menus share a tinted, blurred surface, compact 28px rows and inset corners. The highlighted item paints its own background immediately; pointer movement, keyboard navigation and scrolling keep the same geometry from the first opening. Selection uses the skin's authored choice pair or its accent with a contrasting foreground. Separators remain inset from the outer edge.

Identify keyboard focus with background or text treatment throughout Ling, including shared controls, custom interactions, Markdown, code editors and Pi UI adaptations. Focus decoration excludes outlines, borders, inset rings and shadows. Preserve native focus, keyboard navigation, focus restoration, text carets and selection. Validation borders and persistent surface hairlines are independent of focus.

Escape closes without changing the selection and restores focus to the trigger, including triggers in Pi extension dialogs. Menus use Radix's focus collection and typeahead. Full labels must remain available for truncated project names. Menu actions use the desktop arrow cursor; ordinary controls inherit Ling's cursor and focus treatment.

## Model selection

Model selection opens in an anchored non-modal popover, above its Composer trigger or below its settings trigger. It floats above the editor, transcript and settings fields while they keep their layout positions. Conversation, quickstart, Pi defaults, per-model compaction settings and reference-model selection share one picker. Narrow Composers keep the model trigger directly visible. Opening or closing the picker must preserve the editor instance, draft, attachments and undo history; changing its owning project or conversation closes it.

The selection surface is 440px wide, constrained to the available viewport or containing dialog, and normally 304px tall. When the available viewport height is smaller, only the list area contracts so the search and footer remain reachable. It flips and shifts near an edge without changing surrounding layout. Search and footer stay fixed while provider and model lists scroll independently; empty results and provider navigation keep the same height. At widths below 376px, provider selection occupies the same list area with a back action. Wider panels show a 108px provider rail. Provider filtering uses the actual configured provider, including when a model ID names another provider. The provider rail follows model search results while retaining All providers and the selected provider. Its search action opens the provider page in the same surface; provider search matches provider names and IDs independently of the model query. Each page retains its own query when navigating between them. Browse across all providers by default, or narrow to one without losing the model query. Full model identities remain available on hover.

Search follows Pi TUI's whitespace/slash tokenization, ordered fuzzy matching, letter/number token fallback and relevance ranking. All tokens must match. Search also includes provider display names. Current and known default models lead an unfiltered list; a default prefix finds the supplied default model. A changed query highlights its best result, and matching text is emphasized without changing the label. The search field’s clear action clears only the current page’s query and keeps the picker open. Tab reaches the provider rail as one stop; arrows or Home/End move within it and Enter confirms the provider before returning to model search. Arrow keys move through search results and Enter selects; IME confirmation must not select a model. Escape closes the provider page first, then the picker, restoring trigger focus; selection returns to the Composer editor when applicable. Clicks or focus outside close the picker. Keyboard targets use quiet background feedback.

## Questions and approvals

Permission prompts and asynchronous questions align with the Composer's full width; overlay positioning adds no extra horizontal inset. Preserve complete titles, questions and option descriptions with natural wrapping, including long paths and explicit line breaks. The card body owns vertical scrolling; individual descriptions and approval details do not add height caps or nested scroll areas. Keep actions visible while reading long content.

Host questions and Pi approvals share InteractionCard and InteractionChoice. Keep their distinct response owners and cancellation semantics. Single click selects; a separate confirmation or double click confirms. Multi-question forms advance one question at a time, move keyboard focus into the next question and submit only complete answers. Keep the instruction alongside footer actions. A multi-choice double click confirms the selection made by its first click. Full-width options use native radio or checkbox rows with leading indicators, quiet selected surfaces and wrapped descriptions; compact filter choices retain ChoiceButton. Question cards identify single/multiple selection, keep supplemental text independent of selections, and offer clearing selections for a text-only answer. Text fields have visible labels and bounded content-based height. Pi select/confirm remain single-choice and retain their original result types.

Show only the earliest pending Host question above the Composer. Other requests remain reachable from the global pending entry; finishing the visible request advances to the next. Keep pending requests in that queue with one visible card.

A new input card pulses its edge twice, then keeps a static highlight. While it is visible, pause the conversation's decorative progress animations so motion behind the translucent card does not keep repainting its backdrop. Elapsed time and execution state remain live; normal motion resumes when the card closes.

Question body and question titles use Ling Markdown. Literal operation arguments remain code in approval cards. Selected descriptions use the selected foreground color. Answers appear as user replies, using Pi steering while busy; show the queued answer immediately while a tool is still running. Its durable request identity survives history reload and retry.

## Built-in feature switches

Settings → Plugins presents the seven Ling features as shared toggle rows before Pi package management. Each row links to its owning documentation; adapter settings retain the same link, including while the feature is off. These switches control feature loading and execution as well as visibility. Keep the saved choice visible during reload and report deferred or failed reloads. A disabled feature retains readable history and cleanup actions, with an inline notice linking to Plugins; prevent new work at both the UI and Host. When the master switch is off, permission controls show the disabled state alongside the saved approval mode. Scheduled tasks show suspended triggers while the feature is off.

The MCP switch edits Pi's global built-in extension selection. New installations follow Pi's default; existing installations preserve their saved choice during migration. Project selection and installed replacements govern the current session. Settings provides global/project configuration, effective project entries and the current conversation's timestamped Pi status report. The editor supports executable/arguments, HTTP and advanced JSON, with an exposure selector for Codemode, deferred discovery, direct tools and hidden tools. Access-mode rules govern calls, including nested Codemode calls. Saved servers can define complete connections, while project entries can inherit a same-name global service and override its activation and exposure. The effective list offers project customization without copying credentials. HTTP services expose dynamic OAuth registration and CIMD with explicit identity and callback validation. An existing server's enabled switch controls its selected entry. Show invalid entries and configuration errors without hiding valid siblings. File revision conflicts retain drafts and require an explicit refresh/review. Read failures disable writes until refreshed successfully. Keep actions visible while the editor body scrolls; field errors focus the relevant input and expose accessible descriptions. Removing a project entry explains that a global entry can become effective. Configuration management and `ling_mcp` remain available when execution is off. The global extension selection, service enabled field and skill switch have separate meanings. Session controls follow actual loaded capabilities, including project overrides. Pi-installed command overrides retain their lifecycle. `/mcp` opens the same settings page. Refresh status, reconnect, sign-in and sign-out use the current idle session and return to it for prompts. Show the status timestamp and distinguish pending reloads from verified connections. Codemode results include expandable nested call records with completion state, arguments, timing and errors.

Voice input is off by default and can be enabled in Plugins. The Composer has one voice button: start recording, stop and transcribe, cancel an operation, or retry retained audio. Its context menu contains settings and discard; Plugins also provides a settings entry. While focus is inside the visible Composer, Mod+Alt+V invokes the button, Mod+Shift+Alt+V opens settings, and Escape cancels recording or transcription, including retained audio awaiting a retry. These shortcuts must not capture input from dialogs, menus, terminals or other editors.

First use opens the shared settings dialog to select a local model; show its download size and require an explicit download action. Order models by support for the interface language, then downloaded status and size, and show their actual supported languages. Preserve compatible language choices when changing models, distinguish Mandarin from Cantonese, and show Chinese output conversion only when applicable. Localize microphone failures with a recovery action; retain technical details for other failures. Recording exposes elapsed time and level feedback beside the single button, with a two-minute limit. Transcription adds text to the existing draft for the user to review and send. Preserve audio for an explicit retry after transcription fails, and keep recognized text available if the draft is full. Switching away from the session, hiding the page or disabling Voice stops recording; late results must not enter another draft. The settings dialog and upstream `/voice-settings` command use the same controls.

## Skins, typography and motion

Use semantic action, choice, surface, text and radius tokens. Palette values and artwork belong to the skin resolver. Controls use the palette selected by the resolver. Host feature pages and Pi UI adaptations inherit the active tokens and shared styles; they use the shared focus and cursor rules. Portalled menus use the same active document tokens. Shared controls use the same material on macOS, Windows and Web; native window chrome remains Desktop-owned.

Floating menus start with an 86% tint and a static 24px blur. Dialogs and hints retain at least 94% tint to quiet content behind form fields. The resolver strengthens these materials and their secondary text when the authored palette needs more contrast; solid skins and reduced transparency remain opaque. Surface depth follows the skin's elevation setting. Buttons and fields share compact sizing, quiet permanent edges and restrained press feedback. Nested corners account for their container padding.

Reference resolved shadows with `shadow-(--shadow-floating)` and the corresponding control, input, choice or reading token. Named Tailwind shadow utilities can inline the first-paint value at build time and ignore later skin overrides.

Small desktop UI uses the existing `text-ui`, `text-sm` and `text-xs` scale. Main settings headings use `text-xl`; tool panel headings use `text-base`. Body and wrapped descriptions need comfortable line height. Preserve space for Chinese, English, Japanese and Korean. Changes to language refresh labels without replacing editors or drafts.

Motion must honor both the operating system's reduced-motion preference and the skin's motion setting, including controls already open and Pi UI adaptations. Animate transform and opacity, keep frequently used controls brief, and interrupt previous animations when input changes. Menu highlights appear immediately within the item's fixed geometry.

## Acceptance

Use [AGENTS.md](../AGENTS.md) for test selection and [Development](development.md) for isolated runs and evidence capture. The following matrix defines the interface states to inspect in the rebuilt application.

Actions acknowledge input on the next render, before waiting for persistence, network requests or resource reload. A pending switch shows the requested position and an activity indicator; the authoritative result settles its position and failures remain visible. Pending controls retain keyboard focus while preventing repeated activation; duplicate writes also stay gated at their owner. Background reads preserve the current content, editor focus, scroll position and drafts; only controls that depend on the unfinished operation are blocked. Reserve control geometry so progress feedback does not move neighboring targets.

For asynchronous controls, exercise a deliberately slow real dependency, repeated clicks, failure and retry, and navigation during the operation. Measure input-to-feedback separately from completion time in the rebuilt app; measure application latency from input events and rendered frames. Check typing and Escape while background refresh is pending, plus failure rollback and settled state after returning to the page. Keep measurements and fixtures outside the repository.

For shared controls, inspect first opening, close/reopen, pointer movement, keyboard navigation, Escape and focus return. Check representative application, Host feature and Pi extension call sites, long labels and scrollable lists. Verify light, dark and artwork skins, reduced motion, supported languages, narrow widths and zoom. Record the surfaces actually exercised and any unverified environment; record source inspection separately from visual acceptance.

## Pi configuration and session controls

Pi Settings offers Common and Complete views and an explicit global/project selector. The Complete view shows the native key, effective value, source and configured override. Resetting an override restores inheritance. Terminal-only fields are identified as terminal presentation. Unsaved drafts stay with their configuration scope through navigation; stale revisions require refresh and review, with an explicit draft merge. Pending actions acknowledge immediately and show reload completion, deferred application or a visible error without clearing failed edits.

Session Details is available beside conversation usage and through `/session`. Overview shows current context and cache state plus HTML/JSONL export and JSONL import. Tools changes only the selected tool in the current session. Branches shows the SDK tree, current branch and labels; navigating retains the session file and offers recovered input separately so it cannot overwrite the draft. System Prompt shows the actual SDK prompt with explicit truncation. Extension Parameters exposes registered runtime flags and their types. Mutations wait for an idle session and retain runtime-generation fencing.

Selecting a slash completion inserts text. Submission executes the command once, clears unchanged command text on success and retains edits on failure. `/compact` accepts custom instructions, `/reload` reports the resource reconciliation result, and `/name` updates the managed session title. The model picker opens on configured scoped models and provides an explicit complete-catalog view.

JSONL import creates an independent Pi session in the active cwd. It preserves every history record, labels and extension data while assigning a fresh SDK-generated session identity; existing sessions and drafts retain their owners. Invalid JSONL is rejected before runtime replacement.
